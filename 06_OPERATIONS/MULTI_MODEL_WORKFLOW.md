# Multi-Model Production Workflow

## 1. Core Pipeline
User idea
→ ChatGPT Architect
→ Story Core
→ Character
→ World
→ Outline
→ Dramatic Contract
→ Gemini Writer
→ ChatGPT Red Team
→ Revision Brief
→ Gemini Revision
→ ChatGPT Second Audit
→ QA_PASS / REVISE / REJECT
→ State Update
→ Next Chapter

## 2. Gates
### G0 Story Core
Prove theme, central question, character truth, candidate final choice, counterfactuals.

### G1 Character
Prove psychological choice chain, contradiction, vulnerability and non-substitutable functions.

### G2 World
Prove every core rule changes available choices.

### G3 Outline
Prove causal turns, character choices, relationship movement, foreshadow lifecycle and ending dependency.

### G4 Chapter Ready
ChatGPT creates the Dramatic Contract. Only then does Gemini write.

### G5 Draft Audit
ChatGPT independently audits Causality, Character, Information, Structure, Continuity, Foreshadowing and Dramatic Integrity.

### G6 Revision
REVISE/REJECT produces a minimum repair brief. Gemini revises. ChatGPT does not silently replace the writer.

### G7 Second Audit
Check original defect closure, new defects, state integrity and unauthorized deviations.

### G8 Chapter Closure
Only QA_PASS authorizes the END STATE as authoritative and opens the next chapter.

## 3. Model Boundary
ChatGPT answers:
- Why this story?
- Why this character choice?
- Why now?
- Why this consequence?
- Why this ending?
- Why can this not be replaced?

Gemini answers:
- How does the scene feel?
- How do people speak?
- How does tension unfold?
- How does the reader experience the consequence?

## 4. Reject Loop
REJECT / REVISE
→ identify broken chain
→ minimum repair
→ Gemini revision
→ targeted re-audit
→ regression if upstream changed
→ repeat.

Never silently accept a structural rewrite by the prose model.
Never relabel a known defect as PASS.

## 5. Upgrade Rule
If the same prose failure appears repeatedly, upgrade the architecture or Handoff rule instead of patching chapters individually.

Example:
Repeated outline-like prose
→ strengthen Dramatic Integrity and Dramatic Contract requirements.

## 6. Author Override
Author may retain a known problem.
Record QA_OVERRIDE.
Never treat an override as QA_PASS.
