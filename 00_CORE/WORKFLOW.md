# 工作流

## Stage 1 — Foundation
输出：
- STORY_THESIS
- CENTRAL_QUESTION
- CHARACTER_TRUTH
- FINAL_CHOICE
- FINAL_CONSEQUENCE

先回答：**为什么这个故事必须以这种方式存在？**

## Stage 2 — Character
每个主要人物必须建立：
- Want：表层想要
- Need：真正需要
- Lie：错误信念
- Wound/Ghost：塑造其世界观的过去事件
- Motivation Origin：欲望来源
- Internal Contradiction：自我叙事与真实需求的冲突
- Defense Mechanism：保护自己的方式
- Vulnerability Trigger：防线崩裂条件
- Pressure：什么会迫使其选择
- Stakes：选择失败的代价

## Stage 3 — World
只保留会改变人物选择的世界规则。
每条重要规则回答：
1. 谁受它约束？
2. 能带来什么机会？
3. 需要付出什么代价？
4. 它如何制造冲突？
5. 删除它以后主线是否仍成立？

## Stage 4 — Structure
把外部行动、内部变化、关系变化分开追踪：
- Quest：外部目标
- Fire：内部心理/价值变化
- Constellation：人物关系变化

关键转折必须检查“人物是否有选择”。

## Stage 5 — Writer Handoff
不给正文模型一堆散乱设定，而是交付：
- 本章目标
- 本章前置状态
- 本章必须发生的因果事件
- 人物当前心理
- 信息差
- 禁止事项
- 章末变化
- 伏笔/回收要求

## Stage 6 — Red Team
审稿顺序：
独立上下文 Blind Prose Audit（先冻结正文证据）→ Baseline Comparison → Causality → Character → Information → Structure → Continuity → Foreshadowing → Dramatic Integrity → Prose。

Dramatic Integrity 必须按 ../05_RED_TEAM/DRAMATIC_INTEGRITY_AUDITOR.md 执行；章节关闭必须满足 ../07_VALIDATION/VALIDATION_PROTOCOL.md 的 Chapter Closure Gate。

先审“成立不成立”，后审“写得好不好”。
